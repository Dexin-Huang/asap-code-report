ASAP Code Report: Accessibility and Stress-Testing

A first-time user's experience cloning and running the ASAP humanoid motion imitation codebase

Dexin Huang
COMS6998E · Columbia University · Spring 2026
Paper arXiv Code Course

Abstract

We cloned the ASAP humanoid motion imitation repository from scratch and documented every step a first-time user would encounter. The setup required three separate conda environments (asap, hv_gym, asap_deploy) and the manual resolution of 10+ undocumented dependencies, taking approximately 1.5 hours from git clone to a working demo. We ran Sim2Sim evaluation on all five bundled ONNX policies (APT, CR7, kick, jump forward, Kobe), retargeted five external dance motions from AIST++ onto the Unitree G1 robot, executed a Stage 1 training smoke test (100 PPO iterations, 32 envs, ~11 min), and catalogued four major accessibility gaps: 38 of 52 motions ship without trained policies, bundled checkpoints cover Stage 1 only, Stage 2 requires undocumented rollout data, and external motions need undocumented format alignment.

Custom Motions — AIST++ Dance Retargeting

We downloaded AIST++ dance sequences, converted them from SMPL to AMASS format, and retargeted onto the Unitree G1. This required fixing two undocumented format issues:

  • Scale mismatch: AIST++ uses centimeters; ASAP expects meters. Raw import produces a 100x-scale humanoid.
  • Coordinate frame: AIST++ is Y-up; ASAP / MuJoCo is Z-up. Without rotation the character lies flat on its back.

Setup Experience

From git clone to running Sim2Sim demos: approximately 1.5 hours. Three separate conda environments and 10+ undocumented dependencies required manual resolution.

Step Environment Time Notes
Clone & read README — 5 min Repo is 1.2 GB with bundled ONNX checkpoints
Create asap env asap 15 min IsaacGym preview, torch 2.x, numpy pin
Create hv_gym env hv_gym 20 min Humanoid-Verse fork; missing setuptools, pybullet
Create asap_deploy env asap_deploy 15 min MuJoCo deployment; pinned mujoco==3.1.6
Debug missing deps all 25 min easydict, scipy, onnxruntime, lxml, etc.
First Sim2Sim run asap_deploy 5 min Success on CR7 policy
Reproducibility note: The three-environment setup is not documented in a single place. Each sub-package has its own partial requirements.txt. Several transitive dependencies (easydict, lxml, onnxruntime-gpu) are only discovered at runtime.

Training Smoke Test

100 PPO iterations on the CR7 motion to verify the training loop runs end-to-end. This represents approximately 0.04% of the full 250,000-iteration training budget.

Configuration: 100 PPO iterations, 32 parallel envs, ~11 min wall-clock on RTX 4090 (0.04% of full training).

Not converged: The reward curves show the pipeline executes correctly but 100 iterations is far too few for convergence. Full training (250k iters, 4096 envs) takes ~48 hours on 1x A100.

Key Findings

Major gaps discovered while stress-testing the ASAP codebase:

  • 38 of 52 motions have no trained policy. The repository bundles 52 reference motions but only ships ONNX checkpoints for 14. The remaining 38 motions cannot be evaluated without retraining from scratch (estimated 38 × 48 h = 1,824 GPU-hours on A100).
  • Bundled ONNX = Stage 1 only. The shipped checkpoints correspond to Stage 1 (motion imitation) of the ASAP pipeline. Stage 2 (adversarial refinement) and Stage 3 (sim-to-real transfer) are not represented. Users evaluating the "full ASAP stack" from the repo will only see Stage 1 behavior.
  • Stage 2 data gap: 0 of 52 motions have "action" key. Stage 2 requires motion data with an "action" key populated from Stage 1 rollouts. None of the 52 bundled motion files contain this key. Running Stage 2 requires first completing a full Stage 1 training run and exporting the rollout data—a step not documented in the README.
  • External motions need undocumented format alignment. Bringing your own motions (e.g., from AIST++) requires: (a) SMPL-to-AMASS conversion, (b) cm-to-m scale correction, (c) Y-up to Z-up coordinate rotation, and (d) a specific key layout in the .pkl file. None of these steps are documented.
